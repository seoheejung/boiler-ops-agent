# Phase 7 — 한 명령으로 로컬 실행

## 결과와 범위

사용자는 Docker Desktop을 켜고 프로젝트 루트에서 `npm start`를 실행한다. 기존 도구와 의존성을 사용한다. 화면을 빌드한 뒤 제공하는 로컬 확인 모드이며, 코드 자동 반영이 필요한 수동 개발 모드는 유지한다. 기존 인증·권한과 실제 Kafka 경계를 생략하지 않는다.

```text
npm start → uv → scripts/start.py
                   ├─ 도구·파일·포트 확인
                   ├─ 최초 설정·개인 키 준비 (기존 파일 보존)
                   ├─ Kafka 시작·Topic 권한 준비
                   ├─ Ollama 확인·예측 모델 준비
                   ├─ 화면 빌드 → API → 화면 서버 → CSV 재생
                   └─ 브라우저 열기 → Enter / Ctrl+C → 시작한 프로세스 정리
```

## 호출 계약

- `main(config_dir: Path, no_browser: bool) -> int`: 성공 종료 0, 준비·실행 실패 1. 설정 경로 변경은 격리된 로컬 실행에도 사용한다.
- `Runner.start(args: list[str], name: str) -> Popen`: 비밀을 인수에 넣지 않고 환경으로 전달. 자식 로그는 `artifacts/local-start/`에 보관한다.
- `Runner.wait_ready(probe: Callable[[], bool], label: str, timeout: int)`: 제한 시간과 자식 조기 종료를 확인한다.
- `Runner.close()`: 자신이 시작한 자식 트리만 종료한다. 이미 실행 중이던 Kafka·Ollama는 유지한다. 새로 시작한 Kafka는 stop만 하고 삭제하지 않는다.
- 루트 `package.json`에는 의존성이 없는 `start` 스크립트만 추가한다. lock 파일을 추가·수정하지 않는다.
- `.env.security`가 없을 때 기존 발급 도구를 실행한다. 키 원문은 사용자 터미널에 한 번만 표시하고 실행 로그·검증 아티팩트에는 저장하지 않는다.
- 사용자 요청(2026-10-10): `npm run start:reset-key` → `start.py --reset-key` → `setup-security.py --reset-user operator`. 기존 설정이 있으면 유효성을 검사한 뒤 해당 사용자의 `key_hash`만 원자적으로 교체한다. ID·역할·다른 사용자·Kafka 자격은 유지한다.
- 기존 API 포트가 사용 중이거나 `AUTH_USERS_JSON` 환경 변수가 파일보다 우선하면 키 변경 전에 중단한다. 없는 사용자나 손상된 계정 설정도 새 계정으로 자동 대체하지 않는다.
- Windows 실제 콘솔에서 숨겨진 자식 프로세스의 표준 출력을 상속하면 키 표시가 누락될 수 있다. 자식의 출력·오류를 메모리 파이프로 받아 부모 실행기가 터미널에 직접 전달한다. 키 발급용 로그 파일은 만들지 않으며, 전달 실패를 성공으로 처리하지 않는다.
- 쉬운 실행은 학습 보고서의 시험 시작 행 이상에서 재생해 예측을 확인할 수 있게 한다. 이 선택은 해당 프로세스 환경에만 적용한다.

## 구현 전 실패 검토

| 실패 가능성 | 관찰 가능한 처리 |
| --- | --- |
| Node·uv·Docker·Ollama 미설치 | 필요한 도구 이름과 설치 후 재실행 안내 |
| Docker 엔진 정지 | Docker Desktop을 켜라는 안내, 불필요한 설치·설정 변경 금지 |
| CSV 없음·여러 후보·잘못된 경로 | 실제 경로 지정 안내, 임의 데이터 생성 금지 |
| 기존 설정·키 존재 | 일반 시작은 유지. 명시적 재발급 명령만 operator 해시 교체 |
| 재발급 대상 없음·잘못된 계정·인증 환경 변수 우선 | 명확한 오류와 변경 없는 종료 |
| 재발급 저장 실패 | 원자적 교체로 기존 파일 보존, 키 표시 금지 |
| 실제 Windows 콘솔과 출력 리디렉션의 차이 | 두 환경에서 발급·재발급 결과를 사용자가 읽을 수 있어야 함 |
| 키 출력 전달 실패·자식 오류 | 오류 안내 전달 또는 명확한 실패. 준비 완료로 위장하지 않음 |
| 잘못된 Origin·다른 브로커 설정 | 수동 실행 안내, 사용자 설정 자동 교체 금지 |
| 사용 중인 포트 | 포트 번호와 종료할 본인 서버 확인 안내, 타 프로세스 종료 금지 |
| 설치·빌드·모델 준비 실패 | 단계·로그 위치 안내, 시작한 자식 정리 |
| Kafka/API 연결 실패·시작 중단 | 제한 시간 후 실패, 준비 완료로 표시하지 않음 |
| 준비 이후 자식 종료 | 실패 또는 CSV 재생 완료를 구분하고 사용자에게 표시 |
| 중복 실행 | 포트 검사로 차단 |
| Ctrl+C·Enter 종료 | API 자식까지 정리, 기존 서비스와 데이터 보존 |
| 실제 모델·데이터 불일치 | 데이터 해시 확인 후 예측 모델 재생성 |

## 검증

실제 별도 Compose 프로젝트·임시 자격·CSV·Ollama를 사용한다. 브라우저에서 로그인·WebSocket·LIVE·Source Time·센서 값과 원본 CSV를 대조한다. Enter 종료 후 포트와 자신이 시작한 Kafka의 종료를 확인한다. 잘못된 설정·포트 충돌은 전체 실행 명령을 통해 거부를 확인한다. 입력 해시·단계·화면·성공/실패 결과는 `artifacts/e2e/phase7/local-start/`에 남긴다. 키·쿠키는 남기지 않는다.

재발급 검증은 임시 계정만 사용한다. 새 키의 브라우저 로그인, 이전 키의 401 거부, viewer 키의 유지, Kafka 연결과 기존 설정 보존을 확인한다. 앱 실행 중 재발급 시도와 인증 환경 변수·없는 대상은 변경 전에 차단되는지 확인한다. 실제 사용자 파일과 키는 열람하거나 변경하지 않는다.

출력을 파이프로 수집하는 기존 E2E에서 발견할 수 없었던 Windows 콘솔 차이는 별도 프로세스 통합 검증으로 확인한다. 숨긴 실제 Windows 콘솔에서 운영 코드의 프로세스 실행기와 실제 키 발급 CLI를 사용하고, 콘솔 화면 버퍼에 표시된 키와 임시 설정의 해시를 대조한다. 최초 발급·재발급·CLI 오류 안내·로그 비노출을 확인하고 콘솔 원문은 아티팩트로 저장하지 않는다. 성공/실패와 개수만 기록한다.
