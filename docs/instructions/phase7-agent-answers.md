# Phase 7 — 질문별 AI 응답 검수

## 순서와 범위

현재 Ollama 모델과 기존 공개 CSV를 사용한다. 먼저 수정 전 응답을 기록하고, 서버 답변을 개선한 뒤 같은 입력으로 브라우저 E2E를 실행한다. 새 의존성·설비 제어·모델 교체는 포함하지 않는다.

| 질문 | 필수 답변 근거 |
| --- | --- |
| 선택한 센서의 현재값은? | 선택 Tag, 값, 원본 시각, 근거 ID |
| 최근 온도가 상승하고 있나요? | 최근 이력의 시간 구간과 값, 직전 관측 대비 변화율. 전체 구간과 마지막 변화의 방향이 다르면 구분 |
| 목표 온도와 얼마나 차이 나나요? | 목표 Tag의 결측 상태, 계산할 수 없다는 결론 |
| 5분 예측은 얼마나 믿을 수 있나요? | 예측값·대상 시각, 선택 모델과 Naive의 시험 MAE. MAE는 평균 절대 오차이며 개별 예측의 확률이 아님 |
| 밸브를 얼마나 열어야 하나요? | 관측된 밸브 값과 조작 권고의 구분. 제어 인과관계·허용 범위 미확인으로 조작량 판단 불가 |

## 설계 계약

```text
질문 + 선택 Tag
      ↓
현재 모델의 조회 도구 선택
      ↓
고정 Snapshot의 ReadTools → 원본 경로를 가진 근거
      ↓
질문 유형·필수 근거 확인 → 결론 / 짧은 근거 / 한계
      ↓
API 응답 → 브라우저 표시 → Trace와 CSV 대조
```

- `AgentQuery { question, equipment, tag }` 입력과 소유자·역할·Origin 검증을 유지한다.
- 응답의 `answer`는 결론을 먼저 제공한다. `evidence`는 실제 도구 결과의 경로와 값을 유지하고 `limitations`는 질문에 필요한 한계를 전달한다.
- 모델의 선택과 서버의 구성 결과를 Trace에서 구분한다. 필요한 근거가 없으면 확정적인 판단을 만들지 않는다.
- 원본 Tag·숫자·시각을 서버가 구성한다. 자유 생성한 산업 사실이나 제어값을 응답에 넣지 않는다.
- 수정 전 관측에서 다른 센서 근거 선택과 추이·밸브 질문의 예측 도구 오선택을 확인했다. 현재 모델을 유지하고 선택 Tag 전달·도구 설명·근거 후보 범위를 먼저 보완한다.

```typescript
type Intent = 'current' | 'trend' | 'target_gap' | 'forecast' | 'control' | 'other';
type ToolPlan = { intents: Intent[]; tools: ReadToolName[] };
type Findings = { evidence_ids: string[] };
type Answer = {
  answer: string;       // 질문에 대한 결론
  explanation: string;  // 도구 근거의 값·시각·ID
  limitations: string;  // 해당 판단의 한계
  evidence: Evidence[];
  intents: Intent[];
};
// collect_evidence(call, selected_tag) -> Evidence[]
// compose_answer(intents, selected_evidence, selected_tag, snapshot_status) -> Answer text + gaps
```

- 모델은 질문 유형·도구와 근거 ID를 선택한다. 서버는 선택을 몰래 보충하지 않고 부족한 도구·근거를 `answer_gaps`로 기록하고 판단을 보류한다.
- 이력이 2개 미만이거나 끝값이 결측이면 그 이력 근거만으로 계산 불가를 설명한다. 수치로 변화 방향을 답할 때는 이력과 변화율 근거를 모두 요구한다.
- `get_equipment_status`의 응답 후보는 선택 Tag를 중심으로 구성한다. 이력·변화율, 목표 매핑, 예측 시험 성능, 제어 경계도 도구 결과에서 추적 가능한 후보로 제공한다.
- UI는 `answer`와 `explanation`을 일반 문단으로 나누고, 한계와 Trace 링크를 유지한다. 줄바꿈·모바일 폭·키보드 조작을 확인한다.
- Trace는 `model_plan`, `model_findings`, `model_options`, `elapsed_ms`, `answer_gaps`를 기록한다. 실패도 소요 시간을 남긴다.
- 답변 분류 제목은 검증한 질문 유형으로 서버에서 만든다. 근거가 있는데도 모델이 임의로 '결측'이라고 붙이는 평가 제목은 사용하지 않는다.

## 변경 전 실패 가능성 검토

- 선택 Tag 누락·다른 설비 Tag, 온도가 아닌 센서에서 온도 추정, 결측·파싱 오류를 정상값으로 표현.
- 질문과 다른 도구 선택, 필요한 이력·목표·시험 성능 근거 미선택, 구조화 응답 파싱 실패.
- 이력 부족·끝점 결측·중간 결측·상승과 하락 혼재를 지속 상승으로 단정.
- 목표값 결측을 0으로 치환하거나, 다른 목표와 선택 센서를 임의로 연결.
- 모델 파일 부재·추론 실패·시간 분리 위반, 시험 MAE를 신뢰 확률로 표현, 선택 모델의 성능 열세 누락.
- 밸브 관측값을 권고량으로 표현하거나 제어 인과관계·허용 범위를 추측.
- 조회 도중 새 관측 수신·센서 변경·연결 중단·모델 오류·STALE 상태에서 오래된 값을 현재값으로 단정.
- 근거 경로와 값 불일치, UI와 API 답변 불일치, 세션·Trace 소유권·승인 경계 손상.

## 검증 기록

`artifacts/e2e/phase7/agent-review/baseline/`와 `improved/`에 CSV 해시·시작 행·질문·모델 설정·도구 결과·선택 근거·답변·처리 시간·화면 캡처를 남긴다. 원본 입력 검증 실패와 의미 검수 결과를 구분하고 실패한 질문도 저장한다.

질문별 의미 검수는 위 표와 실제 도구 결과를 기준으로 한다. 입력의 숫자만 포함되어 있다는 이유로 질문에 답했다고 판정하지 않는다. 개선 후에도 도구·근거 선택 문제가 남으면 동일 질문을 사용한 모델 비교의 필요성을 결과에 명시한다.
