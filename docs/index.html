02 / FOLLOW ONE EVENT

원본·관측·판단·변경의 경계

  1. CSV원본 Tag·시각 보존csv_source.rows
  2. Replayrun_id · sequence 부여producer.replay
  3. Kafka단일 Partitionconsume
  4. BoilerState검증·수치 변환·이력apply → snapshot
  5. React / R3FWebSocket · 구독useReading

Backend가 원본 문자열을 검증해 Reading으로 변환합니다. 결측은 null, 파싱 실패는 parse_error로 유지합니다. 화면이 원본 CSV를 해석하지 않습니다.

사용자

설비·센서 선택 → 질문 입력 → POST /api/agent/query

AI 조회

AgentQuery → query_agent → Ollama의 도구 선택 → ReadTools.call → 근거 ID 선택 → 결과·Trace 저장

제안

성공한 재열기 Trace + 요청 의도 → Simulator.propose → 모델의 increase / hold / decrease → 정책 검증 → pending 제안 저장

사람의 승인

승인 자격 + 명시적 확인 + revision → Simulator.decide → SQLite 트랜잭션 → executed 또는 rejected + Audit

현재 승인 인증은 변경 결정 API에 적용됩니다. 조회·Trace·제안 API와 WebSocket의 외부 접근 통제는 부족합니다. 적대적 환경 보안 감사에서 배포 전 과제를 확인하세요.

서비스 경계: 브라우저 ↔ FastAPI, Kafka ↔ Consumer, Backend ↔ 로컬 Ollama, Backend ↔ 파일·SQLite. 원본 데이터가 공개되어 있어도 사용자 질문·제안·승인 자격은 별도의 보호 대상입니다.

센서를 클릭했는데 값이 이상하다면

BoilerViewport / KPI / sensor-list → App.selected → registry.sensors[tag] + telemetry.current.sensors[tag] → Inspector.

위치·분류는 registry.py, 숫자·quality는 state.py, 연결 상태는 telemetry.ts부터 확인합니다. 추이는 별도로 GET /api/sensors/history?tag=…를 조회합니다.

Agent 답변의 숫자는 어디서 왔나

AgentPanel.ask() → agent_query(request: AgentQuery) → ReadTools → query_agent(request, tools). 모델은 허용된 도구와 근거 ID를 선택합니다. 응답 숫자는 도구 결과에서 구성합니다.

GET /api/agent/traces/{trace_id}의 calls·evidence·path를 따라 수치를 대조합니다. 모델 오류는 503과 실패 Trace로 남습니다.

승인 버튼이 Simulator 값을 바꾸는 경로

SimulatorPanel.decide(proposal, approve) → POST /api/simulator/proposals/{id}/decision → Simulator.decide. 인증·confirm·만료·revision·정책을 검사한 후 하나의 SQLite 트랜잭션에서 값과 Audit를 갱신합니다.

화면 버튼 비활성화는 편의 기능입니다. 쓰기 허용 여부는 Backend가 결정합니다.

04 / TYPES BEFORE IMPLEMENTATION

타입과 호출을 먼저 연결하기

아래는 현재 코드에서 추린 계약입니다. Python의 일부 함수는 타입 주석 없이 dict를 반환하므로, 도식의 출력 모양을 이미 구현된 Python 타입 선언으로 해석하지 않습니다.

원본 이벤트 → 관측값

Raw event · Python dictrun_id: string
sequence: integer
source_time, emitted_at: string
measurements: Record<Tag, string>

↓ BoilerState.apply(event, offset)

Reading · types.tsvalue: number | null
raw: string
quality: valid | missing | parse_error
error: string | null

화면에 전달하는 계약

Snapshot · types.tstype: 'telemetry'
current: Telemetry | null
status, kafka: string
stale: boolean
error: string | null

↓ /api/ws → connectTelemetry()

useTelemetry() → Snapshot
useReading(tag: string) → Reading | undefined
usePaused() → boolean

표시는 고정할 수 있지만 서버 수집과 Agent 도구 조회는 계속됩니다.

질문 계약 · Pydantic

AgentQueryquestion: str (1–1000)
equipment: str (1–40)
tag: str | None (≤200)
extra = forbid

↓ query_agent(request, tools)

결과: trace_id, assessment, evidence, answer, status. 실패: AgentFailure → HTTP 503.

변경 결정 계약 · Pydantic

Decisionapprove: StrictBool
confirm: StrictBool
expected_revision: int ≥ 0 (strict)
extra = forbid

↓ decide(proposal_id, decision, authorization)

결과: proposal_id, status, value, revision. 값은 요청 본문이 아니라 저장된 제안에서 읽습니다.

06 / TRY IT LOCALLY

직접 확인하는 순서

저장소 루트에서 PowerShell을 사용합니다. Python 3.13, uv, Node.js 22.12 이상, Docker Desktop과 로컬 Ollama가 필요합니다. 기존 환경이 준비되어 있으면 설치 단계는 건너뜁니다.

처음 준비: 데이터·환경·기존 의존성

원본 CSV를 data/raw/에 배치하고 .env.example을 복사해 필수 환경값을 설정합니다. 실제 승인 토큰은 문서·Git·로그에 기록하지 않습니다.

New-Item -ItemType Directory -Force data/raw
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
uv sync --frozen
npm.cmd ci --prefix frontend
ollama list

필수 환경값: BOILER_DATASET_PATH, REPLAY_INTERVAL_MS, KAFKA_BOOTSTRAP_SERVERS, KAFKA_TOPIC. Agent에는 OLLAMA_BASE_URL, OLLAMA_MODEL도 필요합니다. 모델이 없으면 ollama pull qwen2.5-coder:7b로 별도 준비합니다.

  1. 터미널 1 · Kafka와 API
    docker compose up -d --wait kafka
uv run python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
  2. 터미널 2 · 프런트엔드
    npm.cmd run dev --prefix frontend

    Vite가 출력하는 주소로 접속합니다. 기본 주소는 http://127.0.0.1:5173이며 포트 충돌 시 달라질 수 있습니다.

  3. 터미널 3 · 원본 재생
    uv run python -m backend.app.replay.producer --limit 16

    LIVE와 sequence 증가, KPI와 선택 센서 값 일치, 재생 종료 후 STALE을 확인합니다.

예측과 Agent 확인

uv run python -m backend.app.forecast.train
$env:REPLAY_START_ROW = '42841'
uv run python -m backend.app.replay.producer --limit 16

현재 데이터의 시험 시작 행입니다. 새 데이터에서는 학습 보고서의 test_start_row를 사용합니다. 재열기 센서를 선택하고 Agent 조회 → 답변의 Trace를 확인하세요.

승인과 거절 확인

API 실행 전에 SIMULATOR_APPROVAL_TOKEN을 최소 32자의 임의 값으로 설정합니다. 재열기 Agent 조회 후 제안 생성 → 변경값 검토 → 토큰 입력 → 확인 체크 → 승인 또는 거절합니다.

승인 시 demo_bias와 revision이 갱신되고, 거절 시 값이 유지되는지 Audit에서 확인합니다. 테스트 종료 후 임시 토큰은 폐기합니다.

반복 가능한 검증과 결과 파일
npm.cmd run build --prefix frontend
$env:E2E_PHASE = 'phase7'
node scripts/e2e.mjs
node scripts/review-ui.mjs

Chromium이 준비되지 않았다면 cd frontend; npx.cmd playwright install chromium 후 루트로 돌아옵니다. Phase 7 E2E는 API 8000과 화면 4173 포트를 사용합니다. 4173이 사용 중이면 실행 전에 $env:E2E_FRONTEND_PORT = '4176'처럼 빈 포트를 지정하세요. 프로젝트 Kafka를 일시 중단·복구합니다. 공유 Broker에서는 실행하지 마세요.

artifacts/e2e/phase7/run.json의 passed와 checks, safety-counters.json, 화면 캡처를 대조합니다. UI 검수는 artifacts/e2e/phase7/ui-review/에 별도로 기록됩니다. 생성물은 Git에서 제외됩니다.

이 문서만 보려면 파일 탐색기에서 docs/index.html을 여세요. 외부 CDN이나 문서용 서버가 필요하지 않습니다.

08 / THE NEXT DECISIONS

추후 필요한 작업

아래 항목은 현재 완료 범위에 추가할 검토 과제입니다. 새 Phase가 시작되거나 배포가 승인된 상태는 아닙니다.

01

외부 노출 전 접근 경계

사용자 인증·역할과 자원 권한, WebSocket Origin, 요청·연결·모델 동시 실행 한도, TLS와 보안 헤더를 설계합니다.

완료 판단: 비인가 요청·과도한 요청·교차 출처 시나리오에서 차단과 감사 기록.
02

증거와 데이터의 신뢰

Kafka 생산자 인증·ACL, 승인 근거의 유효 기간·세션 연결, Trace·모델 파일 보호와 보존 정책을 정합니다.

완료 판단: 위조 run·오래된 Trace·변조 파일의 안전한 거부.
03
